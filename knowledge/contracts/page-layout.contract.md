**Page/layout contract (every UI project).** A `kind=page` body is an HTML fragment - a full `<!DOCTYPE>`/`<html>` document is a hard error. The `kind=layout` is the full shell: save one at path `default` and every page picks it up. A page overrides that with `metadata.layout:"<name>"`, and `metadata.layout:"none"` skips the layout template - that is how a pre-auth screen (`/login`, `/signup`) escapes the authenticated nav. `"none"` drops the *layout*, NOT the document: the platform still synthesizes the `<!DOCTYPE>`/`<html>`/`<head>`/`<body>` skeleton around your fragment (and still injects assets and the `<title>`), so a `layout:"none"` page body is a fragment exactly like every other page - never write your own `<!DOCTYPE>` for it. A layout carries `{{content}}` in `<body>` (required, exactly once - an app/SPA shell needs it too: a JS-mount element like `<main id="app">` does NOT replace it, write the content region as `<main>{{content}}</main>`) and `{{assets}}` in `<head>` (optional - without it the platform injects the globals before `</head>` anyway, so include it to choose where they land). The page `<title>` is data-driven, NOT a layout placeholder: the platform writes `<title>` into `<head>` from each page's `metadata.title` (set on the `kind=page` save; a `manage_seo set_meta` `title` overrides it), and it STRIPS any `<title>` the layout hardcodes. So the only layout placeholders are `{{content}}`, `{{assets}}`, and `{{include:name}}` - a `{{title}}` (the templating habit from Handlebars/EJS/Jekyll) or any other invented token is rejected on save; do not put `{{title}}` or a `<title>` in the layout. The homepage is a `kind=page` at path `/` (never `/index.html`, `/index`, or `/home`). Page behaviour ALWAYS ships as a linked `kind=file` JS artifact, never an inline `<script>`: an inline script cannot `import` anything (your modules and the platform helpers are all unreachable from it) and is invisible to the JS gates, so it fails only in the live page. That fragment is the page's mount root: the entry builds INTO the elements the body declares (`document.getElementById('app')`), and never appends a second root to `document.body` - a duplicate full-height root pushes the real UI a viewport down, where the reset's `overflow:hidden` puts it out of the user's reach, so the page looks blank while every probe still reads it as painted. Never hand-write a `<script src>` or `<link rel=stylesheet>` tag for your own files; linking is the platform's job (that one IS rejected on save). The shared design system is one `scope=global kind=file` CSS artifact linked into `<head>` via `{{assets}}`; the layout's own `<style>` is for a minimal reset only (a `:root` custom-property block plus base rules, under ~2KB / 60 lines - a design system inlined there is rejected on save). Reusable fragments are `kind=component`, included with `{{include:name}}`.
